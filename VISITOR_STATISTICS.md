# Shared page-view counter

Implemented 12 November 2026. The footer combines portfolio `counts` and hub `hub_counts` from the existing visitor-insights Site, preserving all history. Before this change, collection required clicking Allow statistics, the two totals were separate, and the portfolio fetched its total only once. Recorded history in this database begins 8 November 2026; do not invent or backfill earlier visits without verified original records.

The collector is https://inam-visitor-insights.boxywatermelon2.chatgpt.site/collect. POST `{mode:"aggregate",path:"/..."}` uses only page path and hosting-provided country, discarding referrer/campaign data. It records daily aggregate counts, with no persistent visitor identifier, cookie, raw IP or individual event log. Existing legacy `consent:true` requests remain compatible. Origin restrictions, bot filtering, privacy headers and short-lived in-memory abuse control apply.

The public API `/api/public-summary?site=all` combines both sections with country codes, total, today, week, month, firstRecordedDay and asOf. No page/referrer details are exposed. Explicit `site=github` or `site=knowledge` remains available for separate reporting. Missing database/error responses use 503, not fabricated zero counts. Unknown countries remain separate. All-time totals have no 90-day limit.

`assets/js/visitor-counter.js` is the shared client. A matching copy is in the Knowledge & Opportunity Site at `public/visitor-counter.js`; `app/visitor-footer.tsx` mounts it on both the native and GitHub readers. Keep those copies and CSS in sync. The script records at most once per document/path; polls and Refresh counts only read totals. It refreshes every 30 seconds while visible and on returning to a page. Failed writes/reads are visible to the reader. Ad blockers and network errors may still reduce coverage.

Browser preference `inam-counter-choice-v2` is allow/deny, never an identifier. Both old opt-out keys are honoured unless the user explicitly resumes. GPC and DNT always disable counting. A notice and footer controls provide an opt-out. No visitor data is used for ads; Google consent is separate. The data model and notice follow aggregate statistical-purpose measurement described in the ICO guidance: https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guidance-on-the-use-of-storage-and-access-technologies/what-are-the-exceptions/

`node --test scripts/test-visitor-counter.cjs` tests preferences, identifier-only article paths and payload validation. The stats Site has `tests/history.test.mjs` and `tests/shared-counter.test.mjs`, using SQLite to check all-time preservation, aggregation across sites, country merging, errors, opt-outs and source-data exclusion. Never send synthetic production views to prove the counter; test with local fixtures or an actual UI page visit. Counters are page views, not unique visitors. Do not label them as unique people or promise complete visitor tracking.

The old Flag Counter sidebar embed is replaced by a link to the shared footer, so readers see one consistent total. Older JS assets remain for cached-page compatibility; active layouts load only the new script. Preserve this setup when updating jobs or other site content.
